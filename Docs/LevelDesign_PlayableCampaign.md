# ProjectSR 첫 플레이 캠페인 제작안

기준 문서: `Docs/LevelDesign_Survival.md` v2  
목표: 새 시스템을 더 늘리기보다 현재 구현을 한 레벨에서 처음부터 끝까지 플레이할 수 있게 연결한다.

## 1. 플레이어가 실제로 하는 일

한 문장으로는 **우주선 밖에서 자원을 회수하고, 운석 경고 전에 귀환해 문을 닫고, 수리와 강화를 반복하여 12일차 태양풍을 버티는 게임**이다.

반복 루프는 다음 다섯 단계다.

1. 선실에서 오늘 태양풍과 필요한 수리·강화 재료를 확인한다.
2. 문을 열고 근거리 또는 원거리 잔해 지대로 나간다.
3. 산소와 인벤토리 칸을 보며 필요한 아이템을 골라 담는다.
4. 운석 경고 또는 산소 부족 전에 귀환하여 문을 완전히 닫는다.
5. 적재, 제작, 수리, 선체·레이저 강화 후 다음 외출을 결정한다.

실패는 선체 파괴, 플레이어 사망 두 가지다. 성공은 `FinalDay=12`의 정산과 태양풍을 생존했을 때다. 머신암은 캠페인 규칙과 UI에서 제외한다.

## 2. 첫 플레이 레벨

새 맵 이름은 `LV_SurvivalCampaign`을 권장한다. 현재 작업 중인 `Lv04_TestFinal`은 기능 통합 테스트로 남기고, 캠페인 맵은 복제본에서 시작해야 작업 중인 블루프린트를 망가뜨리지 않는다.

월드 기준점은 우주선 중심 `(0, 0, 0)`으로 잡는다. 아래 거리는 플레이 감각을 잡기 위한 블록아웃 기준이다.

| 구역 | 위치·거리 | 역할 | 주요 아이템 |
| --- | --- | --- | --- |
| 선실 | 선체 내부 | 적재, 제작, 수리, 강화, 운석 회피 | 시작 보강판 2, 산소통 1 |
| A: 튜토리얼 잔해 | 출입문 정면 20~30m | 처음 나가도 길을 잃지 않는 짧은 왕복 | 고철, 전선, 플라스틱 |
| B: 배터리 잔해 | 오른쪽 35~50m | 레이저 강화 재료 선택 | 고장난 배터리, 전선, 배터리 |
| C: 선체 파편대 | 왼쪽 45~60m | 수리와 선체 강화 선택 | 고철, 보강판, 보강판 묶음 |
| D: 위험 보상 지대 | 출입문 반대 65~80m | 장거리 원정과 희귀 보상 | 칩, 고급 보강판, 대용량 소모품 |

구역은 일직선보다 선체를 중심으로 부채꼴로 배치한다. 어느 구역에서도 우주선의 강한 색상 비콘이 보이게 하고, 큰 잔해가 귀환 방향을 완전히 가리지 않게 한다. D 구역은 선체 뒤쪽이라 시야 전환이 필요하지만 HUD 귀환 표식은 계속 보여야 한다.

### 선실 내부 동선

출입문에서 가장 가까운 순서는 `적재/창고 → 제작 → 수리/강화 → 운석 회피 패널`이다.

| 요소 | 문에서 목표 이동 시간 | 이유 |
| --- | ---: | --- |
| 적재/창고 | 1초 | 귀환 즉시 인벤토리를 비움 |
| 제작·수리 | 2초 | 산소 회복 중 다음 행동 수행 |
| 강화 | 2~3초 | 태양풍 전 의사결정 |
| 운석 회피 | 3초 이내 | 귀환 후 문 닫기까지 포함해 경고 시간 안에 도달 |

패널을 열어도 날짜, 산소, 문 상태, 운석 경고는 가려지면 안 된다. 문은 외부와 내부 양쪽에서 상태를 읽고 조작할 수 있어야 하며, 닫히는 중은 안전으로 표시하지 않는다.

## 3. 아이템의 레벨 디자인 역할

정확한 수치보다 “무엇을 위해 줍는지”가 겹치지 않게 한다.

| 아이템군 | 플레이 역할 | 배치 원칙 |
| --- | --- | --- |
| 고철·전선·플라스틱 | 모든 성장의 기초 | A~C에 항상 보이게 배치한다 |
| 고장난 배터리 | 레이저와 배터리 계열 진입 | B에 군집을 만들어 목적지를 읽게 한다 |
| 보강판 | 즉시 생존 | 선체가 손상된 날에는 근거리에 최소 기회를 둔다 |
| 보강판 묶음 | 슬롯 압축형 보상 | C·D의 눈에 띄는 지점에 낮은 빈도로 둔다 |
| 고급 보강판 | 후반 고효율 수리 | 4일 이후 D 보상 또는 제작으로 연다 |
| 배터리 계열 | 에너지 회복과 후반 제작 | 초반에는 완제품보다 고장난 배터리를 더 많이 준다 |
| 업그레이드 칩 | 진행 잠금 해제 | 운에 맡기지 않고 4·7·10·11일에 획득 기회를 보장한다 |
| 산소통 계열 | 더 멀리 가는 선택권 | 첫날 1개 지급, 이후 A/D에 낮은 빈도로 둔다 |

보강판 묶음은 분해할 때 3칸의 여유가 필요하다. 이를 UI에서 알려 주지 않으면 좋은 보상을 주운 뒤 막히는 경험이 생기므로, 분해 버튼에 필요한 빈 슬롯을 표시한다.

## 4. 12일 진행 구조

### 1막: 1~3일 — 규칙 학습

- 1일: 문 열기, A 구역 고철 회수, 산소 감소, 귀환, 적재를 순서대로 경험한다.
- 1일 첫 운석은 랜덤에 맡기지 말고 한 번 보장한다. 경고 중 “귀환 → 문 완전 폐쇄 → 회피 패널”을 보여 준다.
- 2일: 보강판 제작과 선체 1 강화를 목표로 제시한다.
- 3일: 첫 태양풍 피해를 받은 뒤 수리와 저축의 차이를 이해시킨다.

### 2막: 4~6일 — 선택 도입

- B와 C 구역의 시각적 차이를 강화한다.
- 4일에 칩 1개 획득 기회를 근거리에 두어 선체 2 진행이 랜덤 드롭에 막히지 않게 한다.
- 선체 2 이후 레이저 1을 열고, “회피 난이도 완화”가 아니라 “실패 피해 감소”라는 역할을 설명한다.
- 6일 태양풍은 비축 보강판을 실제로 쓰게 만드는 첫 경제 검증점이다.

### 3막: 7~9일 — 위험 보상

- D 구역을 본격적으로 열고 칩·고급 보강판·대용량 산소통을 배치한다.
- 7일 칩 1개는 보장하되 가장 가까운 곳에는 두지 않는다. 한 번의 계획된 장거리 원정으로 얻도록 한다.
- 운석 경고 빈도를 높여 “조금 더 줍기”와 “지금 귀환하기”가 충돌하게 한다.
- 9일 태양풍 이후에는 선체 4 재료와 당장 수리 재료를 분리해 보관하도록 HUD 목표를 바꾼다.

### 4막: 10~12일 — 최종 준비와 결산

- 10·11일에 칩을 각 1개 얻을 수 있게 해 무작위 드롭 0회도 완주 가능하게 한다.
- 레이저 3은 선택 사항이다. 선체 4와 수리 재료가 부족하면 HUD가 레이저보다 생존을 우선 추천한다.
- 11일 마지막 60초에는 새 원정을 권하지 않고 `최종 태양풍 피해 + 11` 내구도 목표를 강조한다.
- 12일 시작의 정산과 태양풍 피해를 통과하면 `OnGameCleared` 결과 화면으로 전환한다.

## 5. 하루 300초의 리듬

`DayDuration`은 SurvivalLoop에서 독립적으로 설정한다. 산소 최대치나 소모율은 이 타이머를 바꾸지 않는다.

| 시간 | 플레이 의도 |
| --- | --- |
| 0~30초 | 오늘 목표와 태양풍 피해 확인, 첫 목적지 선택 |
| 30~130초 | 첫 채집과 귀환 |
| 130~165초 | 적재, 제작, 수리, 강화 |
| 165~260초 | 두 번째 채집 또는 위험 보상 원정 |
| 260~300초 | 귀환과 다음 날 준비 |

기본 산소 150, 소모 1/초라면 한 번의 외출 목표는 70~100초다. 산소 50에서 귀환 권고, 30에서 긴급 경고를 표시한다. 산소통은 날짜를 늘리는 아이템이 아니라 현재 외출의 실수를 만회하거나 D 구역 체류를 늘리는 아이템이다.

## 6. 데이터 에셋 구성

테스트 에셋을 직접 덮어쓰지 말고 캠페인용 에셋을 만든다.

| 에셋 | 적용 일자 | 목적 |
| --- | --- | --- |
| `DA_Map_Campaign_D01` | 1일 | 느린 스폰, 튜토리얼 자원 중심 |
| `DA_Map_Campaign_D02` | 2일 | 첫 강화 재료 보강 |
| `DA_Map_Campaign_D03` | 3일 | 첫 태양풍 이후 수리 |
| `DA_Map_Campaign_D04_06` | 4~6일 | 배터리·칩·레이저 구간 |
| `DA_Map_Campaign_D07_09` | 7~9일 | 위험 보상과 높은 운석 압박 |
| `DA_Map_Campaign_D10_11` | 10~11일 | 최종 강화와 수리 |

SurvivalLoop의 Maps에는 시작일 `1, 2, 3, 4, 7, 10`으로 연결한다. 각 데이터의 가중치와 운석값은 기준 문서의 표를 시작점으로 사용한다. `MeteorSpawnRate`는 0~1 값이며, MeteorData에는 MeteorItemActor 계열과 올바른 풀 데이터가 연결된 실제 운석 아이템을 사용한다.

고정 보장 자원은 현재 랜덤 `ItemSpawnRate`만으로 만들 수 없다. 첫 플레이에서는 다음 중 하나를 택한다.

1. 가장 빠른 방식: 레벨에 일자별 숨김 액터 군집을 두고 `OnDayStarted`에서 해당 군집만 활성화한다.
2. 정식 방식: SpaceMapData에 거리 구역과 보장 아이템 목록을 추가하고 서브시스템이 날짜 준비 중 생성하게 한다.

첫 통합 플레이는 1번으로 시작하고, 흐름이 검증된 뒤 2번으로 옮기는 편이 안전하다.

## 7. 레벨에 반드시 연결할 것

- 플레이 가능한 Character와 해당 GameMode
- SpaceShipActor 한 개
- SurvivalLoopActor 한 개
- InteriorBounds를 실제 선실 내부에만 맞춘 크기
- SurvivalLoop의 SpaceShip, Player, Maps, DayDuration=300, FinalDay=12
- 문 버튼, 적재/창고, 제작, 수리/강화, 운석 회피 패널
- HUD의 날짜·남은 시간·산소·내구도·문 상태·운석 경고
- OnDayPreparationStarted/Failed, OnDayStarted, OnGameOver, OnGameCleared UI 연결
- PlayerStart를 닫힌 선실 안에 배치

레벨 Blueprint나 테스트 BP에서 별도 아이템 스폰 타이머, MeteorDetect, 날짜 증가, 태양풍 피해를 호출하면 C++ 생존 루프와 중복되므로 제거한다.

## 8. 실제 에디터 작업 순서

1. `Lv04_TestFinal`을 `LV_SurvivalCampaign`으로 복제한다.
2. 캠페인 GameMode를 지정하고 플레이어가 선실 내부에서 시작하는지만 먼저 PIE로 확인한다.
3. SurvivalLoopActor를 배치하고 참조와 InteriorBounds를 설정한다.
4. 캠페인용 SpaceMapData 여섯 개를 만들고 Maps 배열에 연결한다.
5. A~D 구역을 회색 박스와 색상 비콘으로 먼저 블록아웃한다. 아트 배치는 하지 않는다.
6. 제작·강화 테이블과 12종 ItemData를 연결한다.
7. 성공/실패/준비 실패 화면을 이벤트에 연결한다.
8. 1~3일만 빠르게 세 번 플레이하여 동선과 자원 부족을 조정한다.
9. 12일 전체 플레이를 최소 다섯 번 기록한 뒤 아트 패스를 시작한다.
10. 검증이 끝나면 Project Settings의 Editor Startup Map과 Game Default Map을 캠페인 맵으로 바꾼다.

## 9. 첫 플레이 체크리스트

첫 15분 테스트에서는 아래만 합격하면 된다.

- 게임 시작 후 1일차와 남은 시간이 보인다.
- 밖으로 나가면 산소가 줄고, 닫힌 선실에서는 줄지 않는다.
- 아이템을 주워 적재하고 보강판을 제작할 수 있다.
- 운석 경고 후 귀환, 문 폐쇄, 회피가 한 흐름으로 된다.
- 3일차 태양풍이 정확히 한 번 적용된다.
- 머신암 관련 버튼이나 진행 요구가 없다.

전체 캠페인 합격 기준은 다음과 같다.

- 랜덤 칩을 한 번도 얻지 못해도 보장 자원을 회수하면 선체 4에 도달할 수 있다.
- 초보자가 매 구간 3~4회 피격해도 적절한 수리로 생존 경로가 있다.
- 12일 태양풍 생존 후 `Cleared`가 되고 성공 화면이 한 번만 뜬다.
- 기본 시작 맵에서 별도 콘솔 명령 없이 캠페인이 시작된다.

## 10. 아직 구현 또는 BP 작업이 필요한 항목

현재 저장소 기준으로 우선순위가 높은 공백은 다음과 같다.

1. `LV_SurvivalCampaign`과 캠페인 전용 GameMode 생성.
2. 실제 12종 ItemData와 제작/강화 데이터 입력.
3. 일자별 고정 보장 자원 활성화 BP 또는 구역 스포너.
4. 날짜/태양풍/문/귀환/클리어 HUD.
5. Default Map을 캠페인으로 변경.

이 다섯 항목이 끝나기 전에는 랜덤 스폰 테스트를 “게임 전체가 플레이 가능하다”는 판정으로 사용하지 않는다.

## 11. 6일 압축 플레이테스트 프리셋

목표 시간은 10~15분이다. `DayDuration=120`, `FinalDay=7`로 설정하면 1~6일을 각각 온전히 플레이한 뒤 7일 시작에 약 12~15분 내로 클리어한다. 6일차 태양풍 직후 바로 끝내려면 `FinalDay=6`으로 바꾸며, 이 경우 실제 타이머 플레이는 1~5일의 약 10분이다.

### 선체 업그레이드와 레시피 해금

`DT_PT_SpaceShipUpgrade`는 행 구조체 `FSpaceShipUpgrade`를 사용한다. Stat 값은 증가량이 아니라 해당 단계의 최종값이다.

| 행 | 도달 레벨 | 목표일 | 최대 내구도 | 최대 에너지 | 운영비 | 강화 재료 | UnlockRecipeIds |
| --- | ---: | ---: | ---: | ---: | ---: | --- | --- |
| Ship_0 | 0 | 시작 | 35 | 30 | 0 | 없음 | 없음 |
| Ship_1 | 1 | 2일 | 50 | 35 | 4 | Scrap 4, ElectricWire 2, Plastic 1 | PortableOxygenTank |
| Ship_2 | 2 | 4일 | 70 | 45 | 6 | Scrap 7, ElectricWire 3, Plastic 2, UpgradeChip 1 | HighQualityReinforcementPlate, HighCapacityBattery |
| Ship_3 | 3 | 6일 이후 확장 | 95 | 60 | 8 | Scrap 10, ElectricWire 5, Plastic 4, UpgradeChip 1 | UpgradeChip, HighCapacityPortableOxygenTank |

6일 압축 테스트의 필수 목표는 선체 2다. 선체 3은 자원을 잘 모은 플레이어가 미리 목표를 볼 수 있는 다음 캠페인 예고로 둔다. 강화 성공 시 현재 구현대로 내구도와 에너지는 새 최대치까지 회복된다.

RecipeTable의 RowName과 잠금 설정은 정확히 다음처럼 맞춘다. `UnlockRecipeIds`는 RecipeName이 아니라 아래 RowName을 사용한다.

| Recipe RowName | 시작 잠금 | 해금 조건 |
| --- | --- | --- |
| ReinforcementPlate | false | 시작부터 |
| ReinforcementPlateBundle | false | 시작부터 |
| DisassembleReinforcementPlateBundle | false | 시작부터 |
| Battery | false | 시작부터 |
| PortableOxygenTank | true | 선체 1 |
| HighQualityReinforcementPlate | true | 선체 2 |
| HighCapacityBattery | true | 선체 2 |
| UpgradeChip | true | 선체 3 |
| HighCapacityPortableOxygenTank | true | 선체 3 |

선체 강화 BP에서 별도로 CraftingComponent의 Unlock을 호출하지 않는다. `TryUpgrade(SpaceShip)` 성공 경로가 해당 행의 `UnlockRecipeIds`를 해금한다. 제작 화면과 UpgradeComponent가 같은 우주선의 CraftingComponent를 사용해야 하며, 저장 복원 뒤에는 `RestoreRecipeUnlocks`를 한 번 호출한다.

강화 화면에는 `강화 시 해금` 영역을 두어 다음 레벨의 `UnlockRecipeIds`를 미리 보여 준다. 성공 직후 `OnUpgradeStateChanged`에서 RecipeList의 `RefreshRecipeListWidget`을 호출한다. 현재 제작 목록은 잠긴 레시피를 숨기므로 이 갱신이 없으면 플레이어가 해금 성공을 알아차리기 어렵다.

`DT_PT_LazerUpgrade`는 `FLazerUpgrade`를 사용한다. 다음 레이저 레벨은 현재 선체 레벨보다 작아야 하므로 레이저 1은 선체 2 이후에만 가능하다.
